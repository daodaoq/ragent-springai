# P4 检索优化：混合检索 + 重排

> 交付：Qdrant 稠密向量 + MySQL FULLTEXT ngram 关键词两路召回，RRF 融合后经阿里百炼 `gte-rerank-v2` 精排，SSE `sources` 事件带每源相关度分数。

## 检索管线

```
用户问题
  ├─ 稠密向量（Qdrant, dense-top-n=20）   vectorStore.similaritySearch
  └─ 关键词（MySQL FULLTEXT ngram, keyword-top-n=20）  MATCH(content) AGAINST(... IN BOOLEAN MODE)
       ↓
  RRF 融合（k=60，去重键 = Qdrant point id / vector_id，稠密优先）
       ↓
  截断 rerank-top-n=10 个候选
       ↓
  百炼 gte-rerank-v2 精排（取 relevance_score 降序，保留 top-k=5，写入 Document.score）
       ↓
  生成（DeepSeek 流式，带 [N] 引用溯源）
```

**降级链（每阶段独立兜底，不打断问答）**
- rerank 失败 / 未配置 key → 用 RRF 融合结果
- 关键词 SQL 失败（FULLTEXT 索引缺失 error 1191）→ 仅稠密向量
- 关键词未启用（`keyword-enabled: false`）→ 仅稠密向量（等价于 P3 现状）

## 配置（`application.yml` → `ragent.retrieval.*`）

| Key | 默认 | 说明 |
|---|---|---|
| `dense-top-n` | 20 | 向量召回候选数 |
| `keyword-top-n` | 20 | 关键词召回候选数 |
| `top-k` | 5 | 最终返回条数（也作重排 top_n） |
| `rrf-k` | 60 | RRF 融合常数 |
| `keyword-enabled` | true | 关键词通道开关 |
| `rerank-enabled` | true | 重排开关 |
| `rerank-top-n` | 10 | 送入重排的候选数 |
| `rerank-model` | `gte-rerank-v2` | 百炼重排模型 |
| `rerank-api-key` | 复用 embedding key | 默认取 `spring.ai.openai.embedding.api-key` |

## 一次性迁移（手动执行，勿重复）

`document_chunk.content` 加 ngram 全文索引（MySQL 8 内置 ngram，无需装插件）：

```bash
docker exec -i ragent-mysql mysql -uroot -proot ragent < backend/sql/p4_retrieval.sql
# 验证：
docker exec ragent-mysql mysql -uroot -proot ragent \
  -e "SHOW INDEX FROM document_chunk WHERE Index_type='FULLTEXT';"
```

> MySQL 无 `ADD INDEX IF NOT EXISTS`，脚本只跑一次。索引缺失时关键词通道自动降级为仅向量，应用不受影响。

## 关键实现

- **`RetrievalService`**（`com.ragent.web.service`）：编排各阶段 + RRF 融合 + 降级。查询先经 `sanitizeKeyword` 剔除 MySQL 布尔运算符（`+ - < > ( ) ~ * " @`），防用户输入触发 SQL 1064。
- **`DashScopeRerankClient`**：调 DashScope 原生 rerank 接口（非 OpenAI 兼容模式），`Authorization: Bearer <key>`；10s 连接 / 30s 读取超时，防止拖慢 SSE 首字节。
- **`DocumentChunkMapper.keywordSearch`**：`MATCH..AGAINST(.. IN BOOLEAN MODE)` JOIN `kb_document` 取 filename。布尔模式避免小语料 50% 抑制；并列排序噪声由重排阶段校正。
- **score 流**：Spring AI `Document` 原生 `score` 字段（Qdrant 已写余弦分）→ RRF 写归一化融合分 → 重排覆盖为 `relevance_score` → `sourcesJson` 读出，SSE `sources` 事件每项带 `score`。前端 `RagSource` 扩展 `score?: number`，来源卡片显示「相关度 x.xx」。

## 架构调整

`RagService` 从 `ragent-ai` 模块移到 `ragent-web`（`com.ragent.web.service`）——它是检索编排层，放 web 依赖方向正确；`AiConfig`/`ChatService` 留在 `ragent-ai`。检索逻辑收敛到 `RetrievalService`，`EvalService` 无需改动，`ragService.retrieve()` 单漏斗自动测新管线。

## 评测

`POST /api/eval/run`（10 用例）：检索指标 Recall@5 / Precision@5 / MRR / NDCG，回答指标忠实度 / 相关度 / 引用率。

P4 交付后基线：**Recall@5=1.0、MRR=1.0、NDCG=1.0、忠实度 5.0、相关度 5.0、引用率 100%**（Precision@5 受小语料 + 文档级标注限制偏低，属评测设计固有现象）。
