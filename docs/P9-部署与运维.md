# P9: 部署与运维手册

> 面向"在另一台机器 / 生产环境把系统跑起来并维持健康"的操作指南（P8-8f 补充）。

## 一、前置条件

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | 21 (LTS) | 本机路径 `D:\jdk\jdk21`；系统 JAVA_HOME 若指向 17，构建时显式 `JAVA_HOME="D:/jdk/jdk21"` |
| Docker / Compose | 29.x | 中间件一键起；国内源需配 registry-mirrors（见 `~/.docker/daemon.json`） |
| Maven | 3.9.x | 多模块构建 |
| Node | 18+ | 前端 Vite 构建 |

## 二、启动中间件

```bash
docker compose up -d          # mysql / redis / qdrant / minio / elasticsearch / logstash / kibana
docker compose ps             # 等 mysql/redis/es 变 healthy
```

> 若 3306 被本机 MySQL80 占用：`net stop MySQL80` 后再 `docker restart ragent-mysql`。

## 三、数据库迁移（一次性，勿重复）

对**已存在**的库执行；全新安装用 `backend/sql/schema.sql` 建表，无需单独跑迁移：

```bash
MYSQL="docker exec -i ragent-mysql mysql -uroot -proot ragent"
$MYSQL < backend/sql/p4_retrieval.sql   # document_chunk FULLTEXT ngram 索引（缺失时关键词通道降级为仅向量）
$MYSQL < backend/sql/seed_admin.sql     # 初始管理员
$MYSQL < backend/sql/p8_trace_id.sql    # P8：rag_query_log / ai_feedback 补 trace_id
$MYSQL < backend/sql/p8_eval.sql        # P8：eval_result 评测结果表
$MYSQL < backend/sql/p8_source.sql      # P8：kb_document.source（UPLOAD/EVAL）
```

> 应用启动时会自检 FULLTEXT 索引是否存在（`FulltextIndexCheck`），缺失会打醒目标记的 WARN。

## 四、配置密钥

- 复制 `.env.example` 为 `.env` 并填真实 Key（`DEEPSEEK_API_KEY` / `DASHSCOPE_API_KEY` / MinIO 凭据）。
- `backend/ragent-web/src/main/resources/application-local.yml`（已 gitignore）里写死过 Key 默认值，
  **生产请用环境变量覆盖并清掉默认值**（P8-8d 遗留风险）。
- 端口/模型/限流/熔断参数都在 `backend/ragent-web/src/main/resources/application.yml` 的 `ragent.*` 下。

## 五、启动后端 & 前端

```bash
# 后端（8080，context-path=/api）
cd backend
JAVA_HOME="D:/jdk/jdk21" mvn -pl ragent-web -am spring-boot:run

# 前端（Vite dev，默认 5173，代理 /api → 8080）
cd frontend
npm install && npm run dev
```

## 六、指标与监控（P8-8b）

- 暴露端点：`GET /api/actuator/prometheus`（health / info / prometheus）。
- 自定义指标：
  - `ragent_ratelimit_admitted_total` / `queued_total` / `rejected_total` —— 限流放行/排队/拒绝计数
  - `ragent_ratelimit_inflight` / `ragent_ratelimit_queued` —— 在途与排队深度 gauge
  - `ragent_rag_query_latency_*` —— RAG 查询延迟直方图（按 intent 分桶）
- Prometheus 抓取配置示例：
  ```yaml
  scrape_configs:
    - job_name: ragent
      metrics_path: /api/actuator/prometheus
      static_configs: [{ targets: ['<host>:8080'] }]
  ```
- 熔断/降级状态：`GET /api/ai/model-status`（当前生效模型 + 每端点熔断态）。

## 七、备份与恢复

```bash
./scripts/backup.sh          # mysqldump ragent 库 → backups/ragent_<ts>/
# 恢复（示例）：
docker exec -i ragent-mysql mysql -uroot -proot ragent < backups/ragent_<ts>/ragent.sql
```
- Qdrant 向量与 MinIO 原始文件在 named volume（`qdrant-data` / `minio-data`），完整备份需另做卷快照或 `qdrant snapshot`。

## 八、安全清单（上线前核对）

- [ ] `.env` / `application-local.yml` 不入 git；清掉写死的 Key 默认值
- [ ] 覆盖 MySQL `root`、MinIO `minioadmin` 默认凭据
- [ ] Redis / Elasticsearch / Kibana / Qdrant 端口不暴露公网（或加鉴权）
- [ ] 生产把 `GET /api/actuator/prometheus` 用网关/网络 ACL 保护
- [ ] 教师/管理员角色由管理员在「用户管理」授予（自注册一律 STUDENT）
- [ ] `rag_query_log` / `ai_feedback` 含问答明文，按合规需要加保留期清理

## 九、已知运维要点

- 多实例部署：会话用 Sa-Token 内存态（未接 Redis dao），多副本需接入 `sa-token-redis`；限流/记忆/摘要本身是 Redis 分布式，可多实例。
- Docker Compose 已加资源限制（`mem_limit`/`cpus`）与 qdrant/minio 健康检查；应用无 Dockerfile，生产可用 `mvn package` 产物配 systemd/容器。
